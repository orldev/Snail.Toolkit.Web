# Firefox с juggler, но без объявления webdriver

Сборка Firefox, которую Playwright умеет водить и которая при этом не говорит
`navigator.webdriver === true`, плюс рантайм-образ с браузерным сервером, к
которому подключается тулкит.

Что именно изменено, чем замерено и чего стоит — в **[PATCHES.md](PATCHES.md)**.

## Зачем

Playwright собирает Firefox со своим патчем, и в этом патче есть строка, которой
браузер сам себя выдаёт:

```diff
--- a/dom/base/Navigator.cpp
@@ bool Navigator::Webdriver() {
-  return false;
+  // Playwright is automating the browser, so we should pretend to be a webdriver
+  return true;
```

Настройками это не снимается — значение прибито в C++. Снять свойство скриптом
можно, так делают стелс-плагины, но подмена **видна**: геттер перестаёт быть
нативным, а его `toString()` выдаёт подделку.

Замер 13.09.2026 показал, что различие настоящее:

| `navigator.webdriver` | Google |
| --- | --- |
| `true` (штатный Playwright) | `/sorry/` |
| `false`, подменён скриптом | `/sorry/` |
| `false`, нативный (эта сборка) | выдача, 7–11 ссылок |

Одной сборки при этом мало: с поясом `UTC` отказ получает и она. Среда
контейнера — вторая половина ответа, и обе разобраны в [PATCHES.md](PATCHES.md).

## Порядок работы

Три артефакта с разной частотой обновления. Путать их — значит собирать
двенадцать гигабайт там, где нужно две минуты.

### Шаг 1. Собрать браузер — раз в жизни и при обновлении Firefox

```bash
docker build --build-arg JOBS=8 -t ff-juggler-nowd browser
docker run --rm -v "$PWD/browser/out:/out" ff-juggler-nowd
```

Полтора-три часа. На выходе — `browser/out/firefox-155.0.en-US.linux-*.tar.xz`,
82 МБ. Двенадцатигигабайтный `ff-juggler-nowd` остаётся на машине и никуда не
публикуется: это станок, а не изделие.

**Архитектура наследуется от машины:** на маке соберётся arm64, на Windows —
amd64. Браузер запускается только на своей.

Падение линковки с `killed` или `out of memory` — это OOM: пересоберите образ с
меньшим `JOBS`. Правило — не больше, чем ГБ памяти делить на два. Дерево и
тулчейн закэшированы и заново не качаются.

### Шаг 2. Собрать рантайм — после каждой правки настроек

```bash
docker build -f browser/runtime/Dockerfile -t ff-juggler:155.0 browser
```

Минуты. Архив из шага 1 распаковывается внутрь, туда же кладутся семь наших
правок из `preferences/`. Это и есть изделие.

### Шаг 3. Проверить

```bash
docker build -f browser/verify/Dockerfile -t ff-verify browser

docker run --rm -e WARM=1 -e HEADFUL=1 -e FRESH=1 \
  -v "$PWD/browser/out:/out" -v ffbrowser:/browser -v ffprofile:/profile ff-verify
```

Поднимает рядом нашу сборку и штатный Playwright, печатает обе колонки, свойства
среды и ходит в Google. Ключи: `STOCK=1` — вести поиск штатным браузером,
`STOCKCFG=1` — подложить ему наш конфиг, `SPOOF=1` — подменить `webdriver`
скриптом, `TZ` и `SCREEN` — менять среду, `FRESH=1` — чистить профиль. Ими
получены все таблицы в [PATCHES.md](PATCHES.md).

### Шаг 4. Запустить

```bash
docker run -d --name ff-juggler -p 3000:3000 -e TZ=America/New_York ff-juggler:155.0
docker logs ff-juggler
```

В логе первыми строками — пояс, разрешение, версия браузера и число наших правок.
Часовой пояс обязателен и не декоративен: с `UTC` не работает даже эта сборка.

### Шаг 5. Опубликовать — только чтобы отдать другой машине

Шаг нужен не всегда. Там, где вы собирали, образ уже лежит локально, и скачивать
нечего. Публикация — для продакшена, который браузер собирать не будет. Он качает
около 300 МБ (реестр хранит слои сжатыми) и делает это один раз на версию
браузера; выкладки вашего приложения его больше не трогают.

```bash
# токен классический, с правом write:packages
echo "$CR_PAT" | docker login ghcr.io -u orldev --password-stdin

docker tag  ff-juggler:155.0 ghcr.io/orldev/ff-juggler:155.0
docker push ghcr.io/orldev/ff-juggler:155.0
```

В PowerShell первая строка — `$env:CR_PAT | docker login ghcr.io -u orldev --password-stdin`.

Новый пакет в GHCR приватный по умолчанию, публичным становится только руками.
Это правильно: см. «Про имя».

**Две архитектуры** — браузер собран под свою машину, поэтому тегов два, а
манифест один:

```bash
docker push ghcr.io/orldev/ff-juggler:155.0-arm64   # собрано на маке
docker push ghcr.io/orldev/ff-juggler:155.0-amd64   # собрано на машине с Windows

docker manifest create ghcr.io/orldev/ff-juggler:155.0 \
  --amend ghcr.io/orldev/ff-juggler:155.0-amd64 \
  --amend ghcr.io/orldev/ff-juggler:155.0-arm64
docker manifest push ghcr.io/orldev/ff-juggler:155.0
```

Кросс-сборку через QEMU не предлагаю: компиляция Firefox под эмуляцией идёт не
часы, а ночь, и разваливается на Rust или на линковке чаще, чем доходит до конца.

**Реестр можно обойти вовсе.** Если продакшен один и он ваш:

```bash
docker save ff-juggler:155.0 | gzip | ssh server 'gunzip | docker load'
```

А наименьший объём передачи — это вообще не образ, а архив из шага 1: отдайте
82 МБ, и рантайм соберётся на месте за две минуты.

## Подключение к тулкиту

Контейнер отдаёт `ws://<хост>:3000/`, тулкит ходит туда через уже существующую
настройку:

```json
{ "Web": { "Scraping": { "BrowserServer": "ws://ff-juggler:3000/" } } }
```

Версия `playwright-core` в образе должна совпадать с версией Playwright в
тулките — протокол juggler между версиями не согласуется.

**Чего пока не хватает со стороны тулкита:** `BrowserPool` прибит к
`driver.Chromium` на обеих ветках, включая `ConnectAsync`, а клиент Chromium к
серверу Firefox не подключится. Нужен выбор движка (`ScrapingOptions.Engine`);
до него сборка тулкиту недоступна.

## Размеры

| | размер |
| --- | --- |
| сборочный образ `ff-juggler-nowd` | 11 ГБ |
| архив на выходе | 82 МБ |
| рантайм-образ | ~800 МБ |
| из них сам браузер | 307 МБ |
| скачивание из реестра | ~300 МБ |

307 МБ — это пол: сборка уже без отладочных символов, `strip` не даёт ни байта.
Одиннадцать гигабайт сборочного — это дерево Firefox (4.67 ГБ), тулчейн Mozilla
(4.25 ГБ) и инструменты; скомпилированного там нет вовсе, сборка идёт при
`docker run` и живёт в эфемерном слое.

## Требования к машине сборки

| | минимум | комфортно |
| --- | --- | --- |
| RAM | 16 ГБ | 32 ГБ |
| Свободный диск | 60 ГБ | 80 ГБ |
| Ядра | 4 | 8–16 |

Память — единственное настоящее ограничение, её съедает линковка `libxul`. На
маке это память **виртуальной машины Docker**, а не всего компьютера: поднимать
в Docker Desktop → Resources → Memory.

## Что лежит рядом

```
Dockerfile          сборка браузера
runtime/            рантайм-образ: браузерный сервер для тулкита
verify/             проверка: сравнение со штатной сборкой и поход в Google
preferences/        наши правки настроек, их берут и рантайм, и проверка
patches/            снимок browser_patches от Playwright, как есть
PATCHES.md          что изменено, чем замерено, чего стоит
out/                сюда ложится архив (в .gitignore)
```

`patches/` взят из `microsoft/playwright` на 13.09.2026. Ревизия дерева Firefox
прибита в `Dockerfile` (`FIREFOX_REV`) и меняется только вместе с патчами — они
друг без друга не накладываются.

## Про имя

Это **модифицированный** Firefox. Товарные знаки Mozilla не позволяют
распространять изменённые сборки под именем Firefox — по этой причине Debian
годами выпускал Iceweasel. Для приватного реестра вопрос не стоит; при публикации
наружу образ надо называть своим именем, а родство указывать текстом. Код под
MPL 2.0: изменённые файлы остаются под той же лицензией, и исходник правки должен
быть доступен получателю — он приведён в [PATCHES.md](PATCHES.md) целиком.
