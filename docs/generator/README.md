# Генератор документации

Превращает то, что компилятор записал о шести пакетах, в две секции сайта. Проза берётся из
сгенерированных `.xml` — это единственное место, где remarks существуют вне исходников. А вот
**доступность берётся из собранной сборки**, потому что xml её не знает: элемент `<member>` несёт
имя и ничего о том, публичный это тип или внутренний.

Именно поэтому это скомпилированный инструмент, а не скрипт над xml. Скрипт опубликовал бы как
справочник потребителя те самые internal-типы, которые здесь специально закрыли.

```bash
dotnet run --project docs/generator -- docs    # записать docs/content/reference и docs/content/decisions
dotnet run --project docs/generator -- check   # упасть, если на диске не то, что сгенерировалось бы
```

## Две секции — два читателя

| секция | для кого | что берёт |
| --- | --- | --- |
| `docs/reference` | потребитель пакета | только публичные объявления |
| `docs/decisions` | участник проекта | всё, что называет дату, включая internal |

Запись попадает в решения, **назвав дату**. Это то же правило, которому подчиняются комментарии
самой библиотеки: замер отличается от пересказа тем, что у него есть день. И это же делает секцию
счётной.

## Что здесь уже ловилось

**Генераторы пишут в тот же xml.** `[GeneratedRegex]` кладёт в файл `RunnerFactory` и `Runner` под
`System.Text.RegularExpressions.Generated` — по паре на шаблон, с повторяющимися именами. Первая
версия инструмента на этом падала. Отсекается по своему корню пространства имён, а не по имени
чужого генератора: следующий генератор назовётся иначе.

**Тип с первичным конструктором документирован дважды.** Компилятор копирует summary и remarks типа
на порождённый `#ctor`, и без чистки каждая запись появлялась бы как `Effect` и ещё раз как
`Effect.constructor` с тем же текстом — и считалась бы дважды. Сверяются по прозе, а не по виду
члена, чтобы конструктор со своей документацией уцелел.

**Extension-блок C# 14 пишет в id порождённое имя.** `ServiceCollectionExtensions.<G>$7B30…AddSearchClient`
— заголовок должен называть класс, который можно набрать руками. Тот же артефакт заставляет
`find_unused_symbols` считать неиспользуемыми классы регистрации всех шести пакетов.

## Почему `check` — отдельный шаг в CI

Публичный тип, добавленный без перегенерации, и страница, поправленная руками, кончаются одинаково:
расхождением диска с выводом компилятора. Ни то, ни другое не видно никакой другой проверке
репозитория — **отсутствующая страница выглядит ровно так же, как правильная**.
